# Accessibility changes in commit cf7e1d4 (for review)

Scope: WCAG 2.2 AA automated checks (axe-core) on the pages listed in the end-to-end suite. Visual design is unchanged except where noted.

## What changed
1. **Colour contrast.**
   - Gold buttons and step numbers: background darkened from #B08D4C to #8A6A2E (white text 3.1:1 → 5.0:1).
   - Footer brand caption: #7A5F26 at full opacity (was 75% opacity, about 3.5:1 on white; now 6:1).
   - About page eyebrow: inline gold replaced by #8A6A2E.
2. **Links in running text** are underlined (new CSS rule for links in paragraphs, list items and small or muted text; buttons excluded). Colour alone no longer marks a link (WCAG 1.4.1).
3. **Form labels.** About 44 label-and-control pairs (existing and new screens) now have a `for`/`id` pair, so each visible label is programmatically attached (login, apply, contact, portal settings, templates, issuance upload, account security, and the new logo field).
4. **Unlabelled filters.** Five existing filter selects gained an `aria-label` (knowledge categories and types, platform status, schemes status, certificate status).
5. **Scrollable tables.** 78 `.table-wrap` containers (existing and new screens) gained `tabindex="0"`, so keyboard users can scroll wide tables (WCAG 2.1.1).

## Why
Automated checks found these issues on public, admin and provider pages. Each change is the smallest markup or CSS change that removes the reported failure.

## Not changed
- No layout, copy or behaviour changed beyond the points above.
- The labels were added with the existing text; no label was reworded.
- Pages not in the end-to-end suite were not re-checked by this change.
- A manual audit (screen reader and keyboard) is still needed.
