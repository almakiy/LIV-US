# تجربة منصة LIV كاملة على GitHub Codespaces

هذا الدليل لتجربة العملية كاملة قبل استكمال بقية المراحل: إنشاء مزوّد، تصميم الشهادة، الإصدار، مسح الباركود، التحقق، الإلغاء.

## 1) التشغيل
1. من صفحة المستودع على GitHub: **Code ▸ Codespaces ▸ Create codespace on `claude/blissful-sagan-wp14xp`**.
2. انتظر دقيقتين تقريباً. يثبّت Codespaces الاعتماديات، ويهيّئ قاعدة PostgreSQL، ويضيف بيانات تجريبية، ثم يشغّل الموقع.
3. يظهر في الطرفية رابط الموقع وبيانات الدخول (محفوظة أيضاً في ملف `.env`). الموقع يُفتح تلقائياً من تبويب **Ports** (المنفذ 3000).
4. **لمسح الباركود من هاتفك:** في تبويب Ports اضغط بزر الفأرة الأيمن على المنفذ 3000 ▸ **Port Visibility ▸ Public**. بدونها يعمل الموقع لك وحدك فقط.
   كلمات المرور عشوائية، لكن لا تترك المنفذ عاماً أطول من اللازم.

> رمز QR في كل شهادة يحمل رابط هذا الـ Codespace. إذا حذفته أو أنشأت غيره فالشهادات القديمة تشير إلى الرابط القديم.

## 2) سيناريو التجربة الكامل
| # | الخطوة | ما تتأكد منه |
|---|---|---|
| 1 | افتح `/login` وادخل بحساب **Admin** (يظهر الرابط في تذييل الصفحة باسم Staff login) | لوحة الإدارة تعمل |
| 2 | **Training platforms ▸ + New provider** | يُنشأ مزوّد نشط بقالب افتراضي |
| 3 | في صفحة المزوّد اضغط **Act as provider** | شريط برتقالي يوضح أنك تعمل باسم المزوّد |
| 4 | **Templates**: غيّر الثيم (Classic/Modern) وفعّل طبقات الأمان | المعاينة تتحدث فورياً |
| 5 | **Issuance Center**: حمّل `Download sample CSV`، عدّله، وارفعه | ربط الأعمدة تلقائياً، وإظهار الأخطاء قبل الإصدار |
| 6 | افتح الدفعة ونزّل **ZIP** الشهادات | ملفات PDF فيها QR وطبقات الأمان |
| 7 | امسح الـ QR بهاتفك (أو افتح رابط التحقق) | صفحة VALID ببيانات الشهادة والمتدرب |
| 8 | افتح `/verify` وجرّب رقم الشهادة مع اسم عائلة صحيح ثم خاطئ | الاسم الخاطئ يعطي NOT FOUND |
| 9 | **History & Records ▸ الشهادة ▸ Revoke** بسبب | صفحة التحقق تتحول إلى REVOKED |
| 10 | **Return to admin ▸ Audit log** | كل الخطوات مسجّلة باسم حساب الإدارة |
| 11 | **Admin ▸ Content ▸ + New article**: اكتب بصيغة Markdown، ثم **Preview** ثم **Publish** | يظهر المقال في `/knowledge` فوراً، وتختفي المسودات عن العامة |

## 3) بيانات جاهزة للتجربة
- بعد أول تشغيل توجد ثلاث شهادات تجريبية للمزوّد `demo@trainingco.example`. أرقامها تظهر في **Admin ▸ All certificates**.
- **اختبار التلاعب:** غيّر اسم المتدرب مباشرة في قاعدة البيانات، فتتحول الصفحة إلى INVALID:
  ```bash
  psql "$DATABASE_URL" -c "update certificates set recipient_last_name='Changed' where cert_number='LIV-2026-XXXXXXXX'"
  ```
- **واجهة API:** من Provider ▸ Settings أنشئ مفتاحاً، ثم راجع صفحة API docs.

## 4) أوامر مفيدة
```bash
tail -f /tmp/liv.log                 # سجل الخادم
bash .devcontainer/start.sh          # إعادة تشغيل الموقع
npm run test:unit                    # اختبارات الوحدة
node tests/e2e.js http://localhost:3000   # الاختبار الشامل (يحتاج PUBLIC_APPLY=true)
```
لفتح صفحة التقديم العامة وتسجيل دخول المزوّد: غيّر `PUBLIC_APPLY=true` في `.env` ثم أعد التشغيل.

لإعادة البيانات من الصفر: `psql "$DATABASE_URL" -c "drop schema public cascade; create schema public;"` ثم `bash .devcontainer/start.sh`.

## 5) حدود هذه البيئة (للتجربة فقط)
- Codespaces يتوقف تلقائياً بعد فترة خمول، وبياناته تبقى ما لم تحذف الـ Codespace.
- ليست بيئة إنتاج: لا نسخ احتياطي، ولا نطاق خاص، ولا HTTPS خاص بك. قبل الإطلاق الفعلي نفّذ قائمة القسم 13 في وثيقة المعمارية.
